PH-001

MakeLang returns an empty slug when EnableSmartTruncate=false and MaxLength is 0 (the default)

wrong result medium confidence 0.93 failed 3/3

github.com/gosimple/slug.MakeLang · slug.go

EnableSmartTruncate=false, MaxLength=0, Make("a")
Expected
"a"
Actual
"" (slug[:0] since len(slug) >= MaxLength is true)
Property
With MaxLength unset (0), slugs are not shortened, so a simple lowercase word is returned unchanged regardless of EnableSmartTruncate
Repro test 
package slug

import "testing"

func TestReproNonSmartZeroMaxLength(t *testing.T) {
	EnableSmartTruncate = false
	defer func() { EnableSmartTruncate = true }()
	if got := Make("a"); got != "a" {
		t.Fatalf("Make(\"a\") with MaxLength=0 and smart truncate off = %q, want \"a\"", got)
	}
}

AssertionError: Make("a") with MaxLength=0 and smart truncate off = "", want "a"

Why this is a bug

Doc on MaxLength: 'By default slugs aren't shortened.' The non-smart branch `len(slug) >= MaxLength` does not guard MaxLength > 0 (unlike the smart branch).

Independent review: slug.go:131 runs `if !EnableSmartTruncate && len(slug) >= MaxLength { slug = slug[:MaxLength] }` with no `MaxLength > 0` check. With the default MaxLength=0, `len(slug) >= 0` is always true, so every slug is cut to `slug[:0]` and comes back empty. The MaxLength doc says 'By default slugs aren't shortened', and the smart branch at line 144 guards with `MaxLength > 0`, so the missing guard is an oversight and not intended. The repro uses the public API correctly, and a one-line fix is trivial for a maintainer to accept.

PH-002

Make() with MaxLength can return a slug ending in '_' that fails IsSlug

wrong result low confidence 0.85 failed 3/3

github.com/gosimple/slug.MakeLang · slug.go

Input
MaxLength=2, Make("0_0")
Expected
a slug without trailing '_' (e.g. "0") that passes IsSlug
Actual
"0_", IsSlug returns false
Property
All output of Make(text) passes IsSlug (when non-empty)
Repro test 
package slug

import "testing"

func TestReproTruncateTrailingUnderscore(t *testing.T) {
	MaxLength = 2
	defer func() { MaxLength = 0 }()
	got := Make("0_0")
	if got != "" && !IsSlug(got) {
		t.Fatalf("Make(\"0_0\") with MaxLength=2 = %q, not a valid slug", got)
	}
}

AssertionError: Make("0_0") with MaxLength=2 = "0_", not a valid slug

Why this is a bug

IsSlug doc: 'All output from slug.Make(text) should pass this test' and slugs may not end with '-' or '_'. smartTruncate cuts text[:MaxLength] without re-trimming '_' / '-'.

Independent review: The IsSlug doc says all output from Make should pass it, and IsSlug rejects a trailing '_' or '-'. With smart truncation, Make trims the ends first and then calls smartTruncate. smartTruncate cuts at `text[:MaxLength]`, or at the last '-', without re-trimming. So "0_0" with MaxLength=2 becomes "0_", and a cut at a '-' can leave a trailing '_' in the same way. The input is ordinary, the guarantee is documented, and re-trimming `-_` after truncation is a small fix a maintainer would accept.
