I tested 14 properties and reported 1 bug. The repro file fails now with `"AA"` where `"aA"` is expected.

The bug is that `Converter::convert` with the Camel pattern treats a leading empty word as the first word. For example, `-a-a` from kebab to camel gives `"AA"` instead of `"aA"`. The `Pattern::Camel` doc says it lowercases "the first non-empty word". The Sentence pattern has the same flaw: `_a_a` from snake to sentence gives `" a a"` instead of `" A a"`. I reported both as one finding because they share a root cause. The repro covers only the Camel case.

Two other failures I did not report:
- **Idempotence:** converting to Pascal case twice gave different results for `0aA_`. The contract doesn't promise idempotence.
- **Combining mark after `_`:** the two code paths in the boundary splitting treat `_` followed by a combining mark differently. I judged this too obscure to defend.
