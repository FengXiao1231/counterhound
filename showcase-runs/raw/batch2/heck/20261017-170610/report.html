to_shouty_snake_case is not idempotent: full uppercase mapping emits combining marks that are then treated as word boundaries
heck::ToShoutySnakeCase::to_shouty_snake_case
reviewreviewer: The behaviour is real, but the crate never promises idempotence. Word boundaries are defined purely by `char::is_alphanumeric`, so combining marks already split words in any input, including a decomposed 'é'. The `uppercase()` helper deliberately uses the full Unicode mapping, and the same effect occurs in the lowercase path ('İ' lowercases to 'i' plus U+0307). The README's 'unicode aware, internally consistent' wording is loose, and fixing this would need a new design for combining-mark handling that the project has no precedent for.
to_snake_case drops combining marks (they are treated as word separators), so output is not a fixed point
heck::ToSnakeCase::to_snake_case (str)
reviewreviewer: Heck documents no idempotence guarantee. Splitting words on !char::is_alphanumeric is a deliberate design choice: the CHANGELOG says the library uses char::is_alphanumeric for word boundaries in all cases. The lowercase() output for İ and the splitter disagree, but that only shows up on a rare input. The repro is correct, though, and a fix that keeps Mn characters inside words would be small and harmless, so this is a low-severity wart rather than a clear rejection.
